# Company research operations

The previous sources phase requested five years of operational evidence in one response capped at 24,000 output tokens. Reasoning and visible output share that limit, so background execution alone cannot prevent `max_output_tokens` failures. The new workflow uses smaller, checkpointed units through the Responses API. ChatGPT Deep Research has its own orchestration; one API request does not reproduce that workflow.

## Run contract

- One run snapshots ticker, requesting actor, as-of date, prompts, model and pricing version. It covers both reports by default. Concurrent starts reuse the active company run.
- Both reports and every attempt share $25 and 80 minutes from creation, so gathering has about 65 minutes. Gathering stops admitting requests when 15 minutes or $7 must be reserved for verification, writing and publication. Runs created before the 80-minute allowance keep their original 55-minute deadline. Limits are ceilings, not completion guarantees.
- PostgreSQL transactions protect leases and in-flight reservations. At most three requests are in flight; reservations can reduce this further. The SDK has no hidden retries. Unknown submission/cancellation outcomes consume their full reserved liability; known rejected submissions consume zero.
- Reads of an existing provider response retry transient connection errors, timeouts, rate limits and server errors up to three times with bounded backoff. These reads reuse the same response ID and original deadline; they do not submit or charge for another generation. Permanent failures still stop the affected unit.
- Confirmed failed/cancelled provider attempts do not consume the evidence correction: each unit permits two completed responses (initial evidence and one repair), plus at most two transport-recovery attempts. All remain inside the original allowance. Overview and quarter repairs use at most four targeted web calls and retain the prior evidence instead of repeating discovery.
- Correcting a retained evidence packet is verification work and may use the finishing reserve. Fresh discovery still stops at the gathering cutoff; targeted corrections still share the original 80-minute deadline and $25 ceiling.
- A resume reuses evidence, response IDs, prompt snapshots, charged costs and the original deadline. It never grants another allowance. Only the original actor can resume. A distinct **Run Company Research** action starts a new allowance after the prior run is no longer active.
- Before resumed work starts, recover and settle every known pending response, including nested source checks, so finished calls cannot strand the shared concurrency or spending reservations. Reconstruct attempts chronologically so a pending partial correction is merged into its original draft. Recovery reads existing responses without submitting new model work.
- Once the original clock expires and its worker stops, the original actor may explicitly choose **Continue (30 min)** once. This adds one 30-minute work window to the same run, retaining every checkpoint, snapshot, charge and outstanding reservation. It never raises or resets the original $25 spending ceiling. Repeated requests are idempotent; a second extension, exhausted spending, another actor, or a still-live worker cannot extend the clock. Normal resume retains the existing deadline. The progress clock displays the current window.
- A targeted quarter repair can return only the affected quarter and original record IDs. The runner merges that correction into the retained packet, preserving untouched records and quarters, then repeats the full source and coverage validation. Saved repair responses can be recovered without generating the research again.
- A stopped attempt retains its original failure after the deadline passes. Elapsed time stops at the attempt's finish time; the resume window continues to expire. The UI distinguishes an expired resume window from research actively reaching its time limit.
- A completed report is independently saved through the existing governed company-sheet action. Incomplete evidence remains available for inspection and never replaces a company sheet. Existing legacy jobs/reports remain readable.
- After public issuer/calendar planning, research can select relevant Talisman data through the existing governed chat read tools. Two selection rounds allow at most six reads and 80 KB of context. The reads use the requesting actor, prohibit writes, refreshes and site suggestions, and scope company-private reads to the run's ticker. Industry/macro datasets can supply relevant broader context. Alternative-data catalog discovery is available; it does not automatically launch fetch jobs or provision new sources.
- Read results, arguments, relevance reasons, capture timestamps and freshness metadata are snapshotted in the existing report artifact storage. A resume reuses those snapshots. Unavailable, denied or oversized reads are reported as evidence gaps; public-web research continues. A snapshot's capture time is not a historical observation date.
- Private evidence is extracted and verified without web-search tools, alongside the independently gathered public evidence. Prior internal analysis remains analysis, not independent proof. Each private citation must identify a registered snapshot and contain an exact supporting excerpt. Public search cannot introduce a private source. Private-data model requests still pass through existing egress governance and secret redaction.
- Private Talisman citations link to authenticated `GET /api/company-research/{ticker}/runs/{run_id}/sources/{source_id}` snapshots. Only the original requesting actor can retrieve them; responses are not cacheable. Reports retain source provenance and data limitations.
- The **Source files** panel on dossiers, watchlist names, and Company Explorer stores readable PDF, text, Markdown, and CSV files independently of holdings and chat messages. Each file is limited to 20 MiB, 500 PDF pages, and two million extracted characters; scanned PDFs require OCR. Attaching a file to another name preserves an independent copy, so removing it from one name leaves other names and files intact. Workspace members can read files; administrators can upload, attach, and remove them. The **Source Library** page (`/source-files`) lists every uploaded file once, with the names it is attached to; files with identical content are one entry, and deleting an entry removes that content from every name, so later research and Stan no longer read it.
- Research snapshots attached file identities at dispatch and captures selected excerpts before public planning begins, so a failed plan does not prevent reading and checkpointing uploads. Resume reuses those excerpts; private evidence extraction still waits for the plan's assigned sections and quarters. Selected excerpts use at most 36 KB of the existing 80 KB private-context allowance; omitted or partial files are identified as gaps. Uploads enter extraction and verification through the private-only pipeline and never enter public search requests. Their citations retain **Private upload: filename** attribution and link to authenticated original-file downloads. Existing run checkpoints retain captured evidence; new runs and agent reads use the files currently attached to the name. Stan can list and page through these sources in a new chat without reattachment.
- When source gathering stops early, the finishing reserve can verify the evidence already collected. Its draft lists unresearched quarters or sections explicitly and remains incomplete; it cannot publish a company-sheet summary.

## Quality checks

1. Resolve issuer identity and the last 20 reported fiscal quarters, with dates and primary sources. Assign each overview section to a topic.
2. Research management in five four-quarter packets, splitting a truncated packet into two and then individual quarters. Research each overview topic on the public web at high reasoning, keeping figures, names, dates and source passages. Reuse the verified fiscal-calendar sources.
3. Validate exact quarter coverage, dates, source passages and tool-observed URLs. Ignore URL tracking parameters without removing document-identifying query parameters, and resolve genuinely new citations with a focused source check. A documented unsuccessful source search is different from a quarter that was never researched.
   Source checks normalize encoded filenames, deduplicate repeated passages, and can correct page/section locations without rewriting facts. Unobserved citations are checked in sequential batches of at most six distinct URLs, with two tool turns per URL; source count alone never rejects a 20-quarter plan. The plan's six discovery searches need not expose every quarterly release, but each missing URL must be observed and its passages supported by a follow-up check before acceptance. Each batch has a content-based checkpoint, and all calls share the original run's cost and time limits. Resume can revalidate an old failed plan response and reuse successful checks without regenerating the plan. Unsupported sources are saved as negative findings and passed to the evidence unit's one bounded repair with the retained draft; they are not repeatedly rechecked for a positive result. Positive findings still require a tool-observed URL. Status errors summarize source failures; complete URL diagnostics are retained in per-attempt validation artifacts. Source passages contain documentary evidence; search activity and retrieval limitations belong in gaps.
4. Group related initiatives for independent source verification. Every original record must be retained or explicitly rejected. Original promises and deadlines cannot be rewritten; concluded outcomes require later dated evidence.
5. Extract management evidence with medium reasoning. Overview gathering stays at high reasoning so the memorandum keeps the source detail. Use maximum reasoning for reconciliation, narrative judgments and audits. Verification returns compact decisions and corrections without regenerating the ledger; writing/auditing uses packets of up to two sections. Overview writing keeps source passages. Permit one repair of an unsupported section or management summary. Deduplicate source passages without shortening evidence.
6. Render the 16-column tracker deterministically. Preserve disclosures, uncertainties, exclusions and source links. Audit the management company-sheet summary before publishing. Publish the overview by running the finished memorandum through the same Markdown loader as an uploaded overview, so the dossier renders that schema.

These checks reduce unsupported claims; they do not establish that every public disclosure has been discovered. Evidence gaps remain visible in the report and progress display.

Private excerpt checks normalize whitespace introduced by PDF extraction and accept unambiguous named-month dates equivalent to the cited ISO date. Words, figures, source identity and page/excerpt or line anchors must still match. A descriptive suffix such as `page 1, excerpt 1; revenue discussion` does not change that anchor: validation checks the quote inside the supplied excerpt and saves its canonical location. Wrong page/excerpt numbers and unsupported quotes remain invalid. A malformed private record is excluded with an explicit gap without discarding unrelated supported records; an entirely unsupported packet still enters the bounded repair and cannot become accepted evidence.
Private evidence checkpoints retain the unfiltered extraction. Resume revalidates that saved extraction; older checkpoints recover it from the matching saved response artifact. This can restore records excluded by a corrected validator without creating or retrieving a provider response, changing the original spending allowance, or bypassing private-source validation.
Management research can retain attributed analyst observations as separately verified factual context. These observations may inform the narrative but never become rows in the operational-commitment tracker or proof of management execution.
After the bounded verification repair, a supported management promise with missing publication dates can remain in the tracker with its outcome explicitly marked **Insufficient disclosure**. Its original promise, target, and citations are preserved; timing, variance, verification and fix-result judgments remain unverified. This cannot accept dated evidence that precedes the promise, rewrite original targets, bypass source checks, or conceal missing records. The saved repaired decision can be replayed without another model call.

Background response polling and recovery explicitly request the web-search source list, and a repair retains URLs observed in the same unit's earlier attempts. Planning independently checks all quarterly source passages, including URLs already observed in search results: an archive page's appearance in results does not prove its dates. Source checking collects failures across every batch before the single repair, so fixing one archive citation does not consume the repair before a later bad batch is discovered. Upload selection reserves an opening excerpt for each attached file before ranking additional passages; disclosure boilerplate follows substantive passages. Truncated excerpts retain their exact source location and are flagged as partial coverage.

## Pricing and provider limits

Only `gpt-6.1-sol` is accepted until another model has an explicit cost envelope. Requests pin the standard service tier. The current conservative envelope uses $2.50/million input tokens (including possible cache-write pricing), $10/million output tokens, $0.01/web-search call, and a 10% margin. It reserves a 128,000-token search context for each allowed tool turn, the initial turn, and an extra tool result if a batch straddles the call limit. Non-search requests use input and schema bytes plus overhead as a conservative token bound. Output budgets include reasoning tokens. Cached-input discounts are not credited.

The UI reports budget usage with this margin, not an invoice amount. Provider usage settles reservations; missing usage retains the maximum charge. Review rates and context bounds when updating models. Sources: [model limits and pricing](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [tool pricing](https://developers.openai.com/api/docs/pricing), [web search](https://developers.openai.com/api/docs/guides/tools-web-search).

## Validation and recovery

Run `python -m pytest tests/test_company_research.py tests/test_company_research_workflow.py` and `npm run test:smoke -- company-research.spec.ts` from `frontend/` for browser checks. A single real evaluation uses:

```sh
python -m scripts.evaluate_company_research --ticker EL
```

This uses real provider calls and egress governance, isolated local persistence, and `apply=false`. It writes the run ID, response artifacts and result under `tmp/company-research-eval/`. It cannot update company sheets or latest-report pointers. Continue an interrupted evaluation using `--resume RUN_ID` with the same output directory; the original caps remain in effect. Never treat a capped or incomplete evaluation as a successful quality test.

The October 17, 2026 EL pilot did not complete either report within its source-gathering allowance. It retained 19 management commitments across four fiscal quarters. The pilot exposed equivalent quarter-label formatting, citation tracking parameters and repeated evidence payloads; these led to parser normalization, focused citation checks and compact verification decisions. In-flight requests retained their initial, slower reasoning settings, so this pilot does not establish the final configuration's full-report completion rate or equivalence to ChatGPT Deep Research. Keep incomplete reports clearly labeled and evaluate completion quality on subsequent explicitly authorized runs.

Deploy the additive Alembic migration before the new API/worker. The normal `./infra/gcp/deploy-all.sh` sequence does this. The migration retains legacy state. After rollout, verify the deployed commit and migration health, then exercise authenticated settings/status/report endpoints without starting an unapproved paid run.
