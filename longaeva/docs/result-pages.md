# Valuation, evaluation and replay pages (LON-36)

Start the package with `make up`. These pages work without an LLM provider.
Valuation and Replay inspect saved successful runs; create a pair in Scenarios
first if the local database is empty. Evaluation reads the bundled result files
and documents directly and needs no evaluation database rows or seed command.

## Valuation & Actions

Select a run, or follow **Valuation & Actions** from its run detail. The URL
retains `run_id`; a directly linked run is fetched independently of the most
recent 200 runs offered by the selector. Refreshing the list does not change
the selected run.

The page uses `POST /valuation/actions` with only `run_id`, its embedded bridge,
and `GET /valuation/multiples` at the run's exact cutoff. Inputs, position size,
reference price and the versioned decision rule use existing server defaults.
No assumption or rule editing is introduced.

Forward EPS and the 3×3 value grid show USD per share and equity in USD millions.
The earnings-driven bar holds the midpoint multiple; the multiple-driven bar
holds median forward EPS. Both use the same dollar axis extent. The outer
envelope retains the label **not a probability interval**. Historical multiples
show their eligible quarters and source filings. The reference remains a
quarterly buyback average, with its source label and acceptance timestamp.

Hold, add, trim and exit rows show target shares and separate transaction,
slippage, impact and funding costs. The rule version/hash, frozen thresholds,
sizing, holding period and illustrative labels remain visible. Unsupported
responses show the server's reason, no EPS/grid/bars, and no net value gaps.
An unsuccessful run cannot be valued. Failed reads expose an explicit Retry.

## Evaluation

The page renders saved snapshots; it does not collect sources, rerun evaluation,
recalculate forecasts or write results. Each variant retains its saved config
hash, scoring definitions and code versions. Those versions describe the saved
evaluation, rather than claiming that it was regenerated by the current UI.

Forecasts & Baselines shows the seven available model/baseline/ablation reports.
Select a target, horizon, window and origin-detail variant. URLs retain the
filters. Next-quarter aggregates offer overall, primary and extension windows;
four-quarter forecast aggregates are saved overall only, so their window control
is fixed to All windows. Origins without that horizon's score remain visible
with an availability message. Exclusions retain their reasons.

The origin-set count is separate from each metric's scored `n` and coverage
denominator. Financial errors and scores are USD millions; growth errors and
CRPS/WIS are percentage points. Growth forecasts, MAPE, benchmark returns,
drawdowns and exposures are percentages. Company guidance retains its own label;
historical consensus remains unavailable.

Ablations shows the three paired comparisons, counts, wins/ties/losses, coverage,
CRPS/WIS differences and robustness across all 13 saved profiles. It supports
both horizons and all three windows. Positive ablated-minus-full error means
lower error for the full model. The backend projects the large persistence
artifact into summaries, settings and config hashes; duplicated profile reports,
origin comparisons and evidence payloads are not sent to the browser.

Benchmarks preserves the report's exact source labels and approximation footnote,
the scored/unavailable/estimated counts, independent-window aggregates,
per-window results, overlapping-window disclosure, and exclusions. Visa strategy
and buy-and-hold remain explicitly `not_run` with null metrics and their reasons.

Report & Model renders allowlisted package Markdown, including tables, with raw
HTML disabled. Registered document links navigate within the viewer; other local
file links remain text. External HTTP(S) links are retained. Selection survives
reload. Missing documents have explicit availability messages.

## Replay

Follow **Replay** from a run detail, or select a successful run. Replay is an
explicit button action using `POST /runs/{id}/replay`; it does not archive a
forecast or alter saved results. The button disables while the request is in
flight. Changing selection clears the displayed outcome; a response for a
different selected run is ignored.

The page distinguishes exact hash match, numerical equivalence with different
hashes, output mismatch, and changed pinned inputs. It displays recorded and
recomputed hashes, maximum relative difference, differing fields, code versions
and both library environments. Numerical equivalence uses the existing backend
tolerance of 1e-9. Errors do not automatically retry replay.

## Read API additions

| Method | Path | Result |
| --- | --- | --- |
| GET | `/evaluation/reports` | Fixed report/document catalog and availability/owner metadata |
| GET | `/evaluation/reports/{report_key}` | Typed saved forecast, ablation or portfolio projection, or pending state |
| GET | `/evaluation/documents/{document_key}` | Saved Markdown, availability and registered document links |

Unknown keys return 404. Missing known artifacts return a pending response.
Unreadable or invalid existing artifacts return an explicit 500 error; they do
not fall back to another report. Reads open no database connection. Cached report
projections are invalidated by file modification time and size. Existing
`/evaluation-results` and run/valuation contracts remain compatible. No migration
is required. The OpenAPI contract is updated in `docs/openapi.json`.
